# BlockCraft Launcher v0.9.31 · PCL 风格中文 UI 与失败才弹窗的自动更新

日期：2026-11-10

> 功能目标属于「下一正式版」规划；当前先通过独立的 WPF RC 候选构建与实机验收，**不在缺少完整在线验证时冒用 Stable 状态**。PCL2 仅用作用户可识别的信息层级、卡片布局、筛选方式参考。本项目独立实现，不复制第三方图标、图片、源码或商标。

## 1. 安装更新不再正常弹窗

- 点击「下载并安装 · 完成后自动打开新版」是安装的明确用户动作。先执行官方下载、SHA-256 校验、ZIP 安全解压和启动预检查，然后**不再出现“确认安装 BlockCraft Launcher 更新 · 是/否”弹窗**。
- 校验后启动独立更新助手、关闭旧 WPF 窗口；助手等待旧进程结束，再备份旧程序、替换文件、自检新版并自动打开新版窗口。新版窗口的 `ContentRendered` 确认和「更新完成」状态仍保留。
- 下载、校验、无法启动更新助手、文件替换、启动回滚、窗口无法正常确认等**真实故障才提示弹窗**，成功不出现消息框；错误会保留诊断信息。
- 自动检查与自动预下载仍不会未经用户主动点击就安装或关闭程序。正在运行的 Minecraft 游戏进程不被关闭；账号凭据与游戏存档不参与启动器替换。
- 「直接打开新版（不覆盖旧版）」仍是单独的试用功能，旧安装保持不变；其用户授权选择与永久安装的无二次确认不同，详见 `V0930_DIRECT_OPEN.md`。

## 2. 全局 UI 统一

- 所有主页面采用相同的 BlockCraft 导航标题、页面分组、小标题与副标题层级；侧边导航按「游戏 · 版本下载 / 社区 · 在线搜索 / 管理 · 帮助工具」分组。
- 浅色和深色主题均统一卡片、搜索容器、边框、按钮、选中态、标签、图标与文本对比度；响应式换行控制避免长中文标签和版本号挤出窗口。
- Windows 更新中心以页面内文字提示执行过程；避免对成功的普通任务弹阻断式对话框。
- 保留原 WPF C#/.NET Framework 4.8 框架及 PCL 式顶部导航，不影响微软账户、Java 环境、存档、房间实验等既有独立业务流程。

## 4. Windows 自动验收

- `check_pcl_unified_ui.py` 明确检测：永久更新方法中**没有成功时的 `MessageBox.Show`**，但仍有外部更新助手和 `ShowError` 失败路径。
- WPF `--ui-layout-selftest` 依次加载所有主页面并检验 UI 样式；在断网状态下验证 CurseForge 的本页版本筛选，下载任务搜索筛选、Minecraft 版本和整合包分页控件。
- `--download-selftest`、`--auth-selftest`、存档/资源下载/加载器等既有离线检查保持通过。
- ZIP 和单 EXE 依旧各自编译、执行并验证窗口真正渲染；独立更新助手包含故障回滚。
- 每个发布资产生成 SHA-256，受控发布必须等待全部 Windows CI 成功后才能上传 Github Releases。

## 5. 正式版上线前的实机门槛

Windows 10/11 真实用户须验证：旧的 **v0.9.30 RC2 由于自身仍包含确认弹窗，升级到 v0.9.31 RC1 时会最后显示一次旧弹窗**，这是旧二进制无法被新包修改的正常行为。安装 v0.9.31 后，应通过之后的**更高版本**再次测试「下载并安装」，届时不会出现确认弹窗；安装成功后自动打开新主窗口。还需检查 Modrinth 和 CurseForge 在线搜索、分类/版本筛选和图标；安装游戏/模组与整合包成功；浅色/深色、DPI 与 840 像素窗口无遮挡。使用受限权限安装目录、断网和杀软拦截时，失败必须可恢复。

**未经上述实测验收，不将 RC1 宣称为最终 Stable。**
