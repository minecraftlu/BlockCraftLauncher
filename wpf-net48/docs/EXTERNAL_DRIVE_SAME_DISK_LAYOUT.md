# 同一块移动硬盘存放 Minecraft 游戏与下载缓存

## 问题
在此前版本中，游戏下载缓存与 Minecraft 游戏目录不能重叠；当用户直接选择 `E:\`（外置磁盘根目录）为游戏根目录，随后把缓存放到 `E:\Downloads`，安全校验会把它视为游戏目录内的缓存，拒绝保存。两个**相互独立、同一盘符**的目录原本是允许的，但缺少清楚的 UI 配置流程与回归测试，容易误以为必须使用不同磁盘。

## 修复
- 在 `设置 → 启动设置` 和 `设置 → 下载设置` 增加 **同一移动硬盘设置游戏与下载目录**，选择移动硬盘盘符或其下父文件夹后，一次设好两个兄弟文件夹。
- 例如选择 `E:\`：游戏目录 `E:\BlockCraftLauncher\Minecraft`，缓存目录 `E:\BlockCraftLauncher\Downloads`。
- 选择 `E:\MyLauncher`：游戏目录 `E:\MyLauncher\Minecraft`，缓存目录 `E:\MyLauncher\Downloads`。
- 两个目录在**同一个移动硬盘**是允许的，不依赖 Windows 将 USB 硬盘识别为 Removable 还是 Fixed。
- 新设置会显示在两个输入框中，**只有用户点击保存设置才生效**；不执行旧游戏迁移和删除。
- 使用已安装的 Minecraft 游戏时，若已有实例放在旧位置，请保留其原目录并继续使用；修改默认游戏根目录**不会自动移动旧实例**。
- 可直接手动填写两个完全分开的路径。若曾直接使用 `E:\` 作为游戏根目录，推荐按上述布局设置，避免根目录下游戏文件和临时下载包混杂。
- 下载目录仍不能等于游戏根目录，或是游戏目录的父文件夹/子文件夹；不能选择网络共享、系统目录、盘符根或联接点作为下载缓存。
- 只允许形如 `E:\Folder` 的完全限定本地盘符路径，拒绝 `E:relative` 这种虽然 Windows 认为已 rooted 但实际依赖进程当前目录的形式。
- 盘符改变或移动硬盘断开时不会静默改存到 C 盘；操作会提示失败或要求重新选择路径，用户原 Minecraft 和启动器 EXE 不会被删除。

## 回归测试
1. 选择整块磁盘根目录，仅**生成**独立子文件夹路径，不往磁盘根写入文件；两个路径的盘符相同。
2. 选择已有父目录，能生成兄弟文件夹并通过 `TryValidate`。
3. 拒绝完全同路径、父子目录嵌套、UNC、相对路径和盘符相对路径。
4. 游戏根目录与下载缓存目录在保存后都能经 `SettingsStore` 正确读回。
5. 完整 Windows WPF / OneFile / ZIP / Minecraft / Modrinth / CurseForge / 皮肤 / 自动更新回滚回归。

注意：GitHub Windows CI 无法模拟所有真实 USB 移动硬盘断开、电源节能、设备盘符变更和 exFAT/NTFS 情况；这些仍需用户在自己的实际外置硬盘上验证。
