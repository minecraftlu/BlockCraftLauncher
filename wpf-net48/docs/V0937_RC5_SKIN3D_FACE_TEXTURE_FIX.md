# v0.9.37 RC5 候选：3D 皮肤显示第二轮修复

用户在 RC4 实机截图中仍发现皮肤人物主体透明，仅剩一些破碎纹理，尽管 RC4 的网格和透明纹理自检通过。

## 修复措施

- 取消所有身体部位共用一张 64×64 图片作为 WPF ImageBrush 材质的做法。
- 为头、躯干、左/右手、左/右腿的六个朝向，分别从已校验的本地 64×64 PNG 中裁剪对应大小的纹理，绑定在各自的 GeometryModel3D 上。
- 每个面的 UV 坐标统一为 0..1 本地纹理坐标，不再直接把图集 UV 提交到 WPF 的 ImageBrush；防止采样到皮肤图集中周围的透明像素。
- **默认兼容路径**：不通过 ImageBrush 渲染头、躯干、左右手脚的基础层，而是把每个有颜色的像素绘制为真实彩色 3D 面片，同色像素按 ARGB 聚合以降低材质数量。因此即使某些显卡无法正确采样纹理，身体轮廓也不会消失。
- 对透明外层保留 RC4 的逐像素几何策略，并改成逐面裁剪的贴图；不生成全透明的遮挡面。
- 保留鼠标拖动旋转、滚轮缩放、双击复位、自动旋转、外层开关、Steve/Alex 手臂以及本地 DIY 编辑功能。

## 测试门禁

1. 同时测试两种底层路径：逐面裁剪纹理 UV 的正确性，以及默认兼容路径把 Steve/Alex 的 384 个头部基础像素绘制成有色面片；人物本体不依赖 ImageBrush。
2. 头部正面纹理像素必须与本地 SkinEditorDocument 中对应像素一致且不透明。
3. 空外层不能生成几何，单个外层像素必须生成且仅生成一个面片。
4. --ui-layout-selftest 在真实 Windows WPF RenderTargetBitmap 上截图并检查自带青色衣服皮肤是否渲染出足量真实彩色像素；以前仅检查几何数量无法发现 RC4 的视觉回归。
5. 必须先通过 Windows CI 后才发布独立 RC5 预览包，不覆盖 RC4 或稳定版。显卡兼容性仍需用户在实际电脑上确认。
